================================================================================
                    CONTRAINTES DE DOMAINE ET INTÉGRITÉ
================================================================================

CONTRAINTES DE DOMAINE:
─────────────────────
1. Pseudo: Alphanumérique + tiret bas (_), longueur 3-50 caractères
2. Email: Format valide RFC 5322 (si utilisé)
3. Couleur HEX: Format #RRGGBB ou #RGB valide
4. URLs: Protocole http/https valide
5. Dates/Heures: Format ISO 8601 (YYYY-MM-DD HH:MM:SS)
6. Hue (HSL): [0, 360] degrés
7. Nombres likes/commentaires/vues: [0, +∞)
8. Tailles images: [1 byte, 10 MB]
9. Type MIME: Énumération (image/jpeg, image/png, etc.)
10. Booléens: {0, 1} ou {true, false}


CONTRAINTES D'ENTITÉ (Règles Métier):
──────────────────────────────────────
1. Unicité pseudo: Pas deux utilisateurs avec même pseudo
2. Auto-abonnement: Un utilisateur ne peut pas se suivre
3. Doublons likes: Un utilisateur ne peut liker qu'une fois par entité
4. Conversation: user1_id < user2_id (unicité de paire)
5. Hiérarchie commentaires: comment_parent_id ≠ comment_id
6. Story expiration: Automatique après 24h (ou paramétrage custom)
7. Message lu: Peut passer de non-lu à lu, jamais l'inverse
8. Archivage conversation: Réversible
9. Suppression logique: Soft delete recommandé pour notifications/messages
10. Photo profil: Optionnelle à inscription, modifiable après


CONTRAINTES RÉFÉRENTIELLES (Intégrité Référentielle):
──────────────────────────────────────────────────────
Politique CASCADE: Cascade delete pour
  • Publications d'un utilisateur supprimé
  • Images d'une publication supprimée
  • Commentaires d'une publication supprimée
  • Messages d'une conversation supprimée
  • Stories d'un utilisateur supprimé
  • Notifications à un utilisateur supprimé

Politique RESTRICT: Restriction si
  • Suppression d'un utilisateur avec conversations (archiver d'abord)
  • Suppression d'un utilisateur suivi (restriction possible)

TIMESTAMPS SYSTÉMATIQUES:

Tous les enregistrements doivent avoir:
  • created_at: Date/heure de création (INSERT = NOW())
  • updated_at: Date/heure dernière modification (UPDATE = NOW())

Exceptions: story (expiration manuelle), message (pas de modification)


VERSIONNING AUDIT (Recommandé):
────────────────────────────────
Pour entités critiques (USER, POST, COMMENT):
  • Version: Numéro de révision (audit trail)
  • Modified_by: ID utilisateur ayant fait la modification
  • Change_log: Description du changement


SUPPRESSION LOGIQUE (Soft Delete):
──────────────────────────────────
Recommandé pour: USER, POST, COMMENT, STORY
Implémentation:
  • Ajouter colonne: deleted_at (DATE-HEURE NULL par défaut)
  • Marquer plutôt que supprimer: UPDATE ... SET deleted_at = NOW()
  • Filtrer dans les requêtes: WHERE deleted_at IS NULL
